## 1. Executive Summary & Tech Stack

**What it is:** A Next.js 16 marketing/catalog **website for a real-world steel-cabinet dealer/showroom** in Dasmariñas, Cavite, Philippines (selling since 2024). It is **not** an e-commerce store and **not** a hardware/software project — "Steel Cabinet" is the physical product being sold. The site showcases the catalog, gallery, ordering instructions, and lets a **single admin** manage live stock, prices, and products through a protected dashboard.

**Conversion model:** No cart, checkout, or accounts. Customers contact via Facebook / WhatsApp / Viber / phone. Payment is offline ("pay at pick up" or "pay after delivery").

## 3. System Architecture & Data Flow

### Architectural Pattern
**Next.js 16 App Router with React Server Components for reads, Client Components for interactivity, Route Handlers as the backend, and a layered repository/service data-access library over Supabase/PostgREST with a local-JSON dev fallback.** Stateless HMAC-cookie auth with two-tier guarding. No Server Actions.

Layering:
- `lib/catalog.ts` — product repository (`getActiveProducts`, `getAllProducts`, `getProductById`, `createProduct`, `updateProduct`, `deleteProduct`).
- `lib/inventory.ts` — service joining catalog products with stock/price.
- `lib/products.ts` — domain/transport types.
- Pure domain utils: `availability`, `inventory-validation`, `format`, `csrf`, `login-rate-limit`, `lightbox`.
- Auth split: `auth-core.ts` (pure crypto, testable seam) + `auth.ts` (Next cookie glue).

### Data flow — public browsing
```
Browser GET /  (force-dynamic, no-store)
  -> app/page.tsx -> <Products/> (async server component)
     -> getInventory() -> getActiveProducts()
        |- Supabase REST: GET cabinet_products?active=eq.true&order=item_number.asc
        |- fallback: data/catalog.json (filtered active)
     -> readSupabaseRows()/readLocalRows() -> merge (missing stock = 0)
  -> <ExpandableGallery/> -> <ProductCard/> (client lightbox)
```
Production without Supabase config: `getSupabaseConfig()` throws; `Products` catches and renders an empty listing (fail-safe).

### Data flow — admin login
```
GET /admin -> proxy.ts verifies HMAC cookie -> invalid: 302 /admin/login
POST /api/admin/login {username,password}
  -> getClientAddress -> canAttemptLogin (429 if >5/15min)
  -> isSameOrigin (403)
  -> verifyAdminCredentials (timing-safe username + scrypt password)
     -> success: clearLoginAttempts -> setAdminSession (HttpOnly/Secure/SameSite=Lax, 8h)
```

### Data flow — admin inventory edit
```
AdminDashboard.saveStock
  -> client validation -> PATCH /api/inventory {productId, stock, price?}
     -> requireAdmin (401) -> isSameOrigin (403)
     -> updateInventory(): getProductById -> parseStockValue/parsePriceValue
        -> Supabase upsert POST cabinet_inventory?on_conflict=product_id
        -> or local atomic write data/inventory.json (mode 0600)
     -> revalidatePath("/") -> {product}
```

### Data flow — admin product CRUD + upload
```
Add:    POST /api/products -> slug id + createProduct (insert product + inventory; retry item_number)
Edit:   PATCH /api/products/[id] (+ conditional PATCH /api/inventory)
Delete: DELETE /api/products/[id] -> soft delete (active=false)
Upload: POST /api/upload -> ensureBucket("product-images") -> Supabase Storage -> public URL
Logout: POST /api/admin/logout -> clearAdminSession -> redirect /admin/login
```

### Data schemas
**`public.cabinet_inventory`** (`001_cabinet_inventory.sql`): `product_id` text PK · `stock` int NOT NULL DEFAULT 0 CHECK >=0 · `price` text NULL · `updated_at` timestamptz. RLS on; anon/authenticated revoked; service_role granted SELECT/INSERT/UPDATE. Seeded 15 ids.

**`public.cabinet_products`** (`002_cabinet_products.sql`): `id` text PK · `item_number` int NOT NULL UNIQUE · `brand` text · `name` text · `price` text · `dimensions` text · `images text[]` · `preorder` bool · `active` bool · `created_at`/`updated_at`. RLS on; service_role full CRUD. Seeded 23 products; backfills inventory; creates public `product-images` bucket.

**`data/inventory.json`**: `{ product_id, stock, price?, updated_at? }[]` (23 rows, all stock 0).
**`data/catalog.json`**: full `CatalogProduct[]` (23 rows), mirrors migration 002 seed.

**In-memory**: login attempts `Map<key,{attempts,resetAt}>`; session payload `{sub,iat,exp,nonce}` signed with HMAC-SHA256.

## 4. Key Modules & Component Breakdown

### Authentication & security
- `lib/auth-core.ts`: scrypt verify (N=16384, r=8, p=1, 64-byte key), `timingSafeEqual`, HMAC-SHA256 base64url session token, 8h TTL, cookie name `onebyte_admin_session`. Enforces `SESSION_SECRET` >=32 chars.
- `lib/auth.ts`: HttpOnly, Secure-in-prod, SameSite=Lax cookie.
- `proxy.ts`: Next 16 "proxy" convention (replaces `middleware.ts`), matcher `/admin/:path*`; guards pages only, not `/api/*`.
- Per-route `requireAdmin()`/`isAdmin()` re-checks in every sensitive handler.
- `lib/csrf.ts`: `isSameOrigin()` — returns `true` when `Origin` header is absent.
- `lib/login-rate-limit.ts`: in-memory per-process throttle (5/15min), trusts `x-forwarded-for`.

### Domain / data
- `lib/catalog.ts`: raw PostgREST `fetch`, memoized `ensureTable()` (attempts `exec_sql` RPC DDL — not defined in migrations), typed `CatalogError`, atomic local writes (tmp+rename), soft delete, item-number allocation with up to 50 retries.
- `lib/inventory.ts`: merges catalog + stock/price; `price` override; Supabase upsert `on_conflict=product_id`; HTTP-400 back-compat retries without `price`.
- `lib/inventory-validation.ts`: `MAX_STOCK=2_147_483_647`, `MAX_PRICE_LENGTH=100`.
- `lib/availability.ts`: preorder > in-stock > out-of-stock.
- `lib/format.ts`: custom Peso display/input formatting.

### UI
- Public sections: `Navbar`, `Hero`, `Products` (server, fail-safe), `ExpandableGallery` (motion drawer), `ProductCard` + `Gallery` (shared lightbox engine: drag/swipe, 1–3x zoom, wheel, keyboard, portal), `HowToOrder`, `About`, `Faq`, `Reveal`, `SmoothScroll`.
- Admin: `AdminDashboard` (main client state machine: products/drafts/priceDrafts/errors/savingId/notice/showAddForm/editingProduct/deletingProduct), `AdminLoginForm`, `ProductForm` (dimensions H×W×L + cm/in, multi-image upload), `PriceInput`.

### Config essentials
- Env: `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`, `SESSION_SECRET`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY` (legacy alias `SUPABASE_SERVICE_ROLE_KEY`). All server-only, never `NEXT_PUBLIC_`.
- `next.config.ts`: remote images only `*.supabase.co/storage/v1/object/**`; headers `nosniff`, `frame-ancestors 'self' https://*.vercel.app`, `strict-origin-when-cross-origin`, Permissions-Policy off for camera/mic/geolocation.
- Deployment: Vercel; Supabase project for Postgres + Storage; migrations run manually in Supabase SQL editor.

## 5. System State & Gaps (TODO / Risks)

No `TODO`/`FIXME`/`HACK` markers exist anywhere in the repo. Inferred gaps:

1. **Runtime auto-DDL smell** — `ensureTable()` calls an `exec_sql` RPC not defined in any migration; if absent it throws "run the migration manually".
2. **Migrations not idempotent** — `002` uses bare `CREATE POLICY` without `IF NOT EXISTS`/`DROP POLICY`; re-running errors. Policies are broad (any role).
3. **Item-number allocation unstable** — only counts *active* products + brute-force retries, so soft-deleted numbers can be reused/collide.
4. **No tests, no CI** — no test script/deps, no workflow, no `vercel.json`.
5. **`AGENTS.md` references missing resource** — mandates reading `node_modules/next/dist/docs/`, but `node_modules` is not installed and that path doesn't exist.
6. **Rate limiting per-instance/ephemeral** — in-memory Map resets on cold starts; not shared across serverless instances; trusts `x-forwarded-for`.
7. **CSRF permissive** — `isSameOrigin` returns `true` when `Origin` absent (defense-in-depth only).
8. **Upload path uses unsanitized `product_id`** in the storage key (`app/api/upload/route.ts`) — object-path manipulation risk.
9. **Soft delete only** — images never cleaned; UI wording ("Remove Product") is misleading.
10. **Silent fallbacks** — Supabase read failures fall back to committed local JSON, potentially masking production incidents and serving stale data.
11. **Price is free-form text** — no monetary guarantees; complex custom formatter.
12. **Hardcoded content** — contact channels, Facebook ID, map coordinates, FAQ, gallery list, seed catalog/prices are not CMS-driven.
13. **Missing app infra** — no error/loading/not-found boundaries, no health endpoint, no pagination; single hardcoded admin (no roles).
14. **Broad CSP embed allowance** — `frame-ancestors ... https://*.vercel.app` permits embedding by any Vercel origin (deliberate for portfolio use, but broad).
15. **Dev data files committed** and can drift from Supabase source of truth.

## 7. Applied Hardening — Tier A (code-only, no data changed)

Applied under the constraint that all persistent data (`data/*.json`, Supabase tables, Storage
objects) must remain untouched, unchanged, and protected. No migration was run and no row/file was
modified.

1. **Upload path sanitized** — `app/api/upload/route.ts` now validates `product_id` against
   `^[A-Za-z0-9_-]+$` (max 100 chars) and falls back to `"unknown"`, preventing object-path
   manipulation in the storage key.
2. **CSRF hardened** — `lib/csrf.ts` no longer fails open when `Origin` is absent; it now falls back
   to `Sec-Fetch-Site: same-origin`, then a same-origin `Referer`, otherwise denies.
3. **Fail-loud reads in production** — `lib/catalog.ts` read paths (`readSupabaseAll`,
   `readSupabaseActive`, `readSupabaseOne`, `getNextItemNumber`) now throw `CatalogError` instead of
   silently falling back to committed JSON. Local JSON is used only when Supabase is unconfigured
   (development). New `CatalogConfigurationError` distinguishes missing config (storefront renders
   empty via `components/Products.tsx`) from real read failures (surface to the error boundary).
4. **`AGENTS.md` corrected** — removed the dependency on the nonexistent
   `node_modules/next/dist/docs/`; points to official Next.js docs with a conditional note.
5. **Boundaries + health** — added `app/error.tsx`, `app/loading.tsx`, `app/not-found.tsx`, and a
   read-only `GET /api/health` that probes Supabase reachability without mutating data.
6. **Tests + CI** — added `tests/auth-core.test.ts` (Node built-in `node:test`, no new deps) and
   `.github/workflows/ci.yml` (`npm ci` → `lint` → `tsc --noEmit` → `test` → `build`). `package.json`

7. **Soft-delete UX relabeled** — "Remove/Remove Product" relabeled to "Hide/Hide Product" with copy
   clarifying no data is deleted and it can be restored.

## 12. Invariants, Subtle Behaviors & Latent Issues (observations, not fixed)

1. **Empty-image products can crash the admin UI.** `ProductForm` allows saving with zero images
   (`validate()` never checks `images`), but `AdminDashboard.tsx` renders `<Image src={product.images[0]}>`
   unguarded in the edit-card grid → `next/image` receives `undefined`. Public `ProductCard` degrades
   gracefully (no thumbnails). Consider requiring ≥1 image or guarding the src.
2. **`createProduct` retry masks non-conflict errors.** The 50-attempt loop catches *any* error and
   only increments the item number, so network/permission failures look like collisions.
3. **Duplicate carousel logic** in `ProductCard.tsx` and `Gallery.tsx` (~200 lines each) — a shared
   hook/component would reduce drift.
4. **`Reveal` can flash.** `hidden` initializes `false` (SSR visible), then `useLayoutEffect` hides
   below-fold elements — a brief visible frame is possible before scroll reveal.
5. **`proxy.ts` uses `node:crypto`** (via `auth-core`) but declares no runtime; confirm it executes
   on the expected runtime on Vercel (route handlers explicitly set `runtime="nodejs"`).
6. **`getSupabaseConfig` auth model:** with a modern `sb_secret_…` key only the `apikey` header is
   sent; the `Authorization: Bearer` header is only used for the legacy `SUPABASE_SERVICE_ROLE_KEY`.
7. **Local dev data are duplicates** of the SQL seeds (`data/catalog.json`, `data/inventory.json`)
   and can drift from Supabase.
8. **No dynamic product routes / pagination:** all 23 products render on the single home page; no
   `/products/[id]` pages, so per-item SEO/sharing isn't possible.
9. **Inventory HTTP-400 fallback** in `readSupabaseRows`/`writeSupabaseRow` silently drops the
   `price` column for older schemas (intended back-compat, but hides schema drift).
10. **`formatPriceDisplay`/`formatPriceInput`** are custom and non-monetary; keep prices as text
    (see Tier B decision).
11. **Hardcoded reactive content:** contact channels, FAQ, gallery list, map coords, seed catalog and
    prices all live in source — changing them requires a deploy.
12. **Verification now run locally** (Node 22.23.3 installed under `/tmp/opencode`): `lint`,

# SESSION 5 — Catalog JPEG Export + "Onsite Assembly Recommended"

## One-click JPEG catalog export
- **`app/api/image-proxy/route.ts`** (new, admin-only): streams Supabase Storage images through our
  origin so the canvas is never tainted. Pins to the configured `SUPABASE_URL` host (falls back to
  `*.supabase.co`), requires the `/storage/v1/object/` path, refuses redirects, and only returns
  `image/*` bytes.
- **`lib/catalog-image.ts`** (new): renders all active products into one JPEG on a `<canvas>` —
  branded header/footer, 3-column grid; each cell shows photos, `Item #`, name, price (formatted),
  dimensions, and availability status only (In Stock / Out of Stock / Pre-Order — no numeric stock
  count and **no brand** in the export). Fetches images (local direct, remote via
  the proxy) → blob → `createImageBitmap` → `toBlob("image/jpeg", 0.92)`. Guards oversized canvases.
  Photos render like the card: up to two side-by-side in rounded slots, **contained** (never cropped,
  whole cabinet visible) on a soft beige letterbox; one image shows centered.
- **`components/admin/AdminDashboard.tsx`:** "Download catalog (JPEG)" button beside *Add Product*;
  generates and downloads `onebyte-catalog-YYYYMMDD.jpg` in one click, with a generating state.
  An inline "Include:" checkbox row (In Stock / Out of Stock / Pre-Order, all on by default) filters
  what goes into the image. Filtering keeps each product's website `displayItemNumber`, so exported
  item numbers still match the client site (gaps allowed when a category is excluded).
